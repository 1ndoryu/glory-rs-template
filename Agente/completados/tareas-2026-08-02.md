## 028A-3 — Dev launcher: auto-recuperación de drift de migraciones (42P07)

- **Que:** `npm run dev` fallaba con `error: while executing migration 20260801140000: ... la relación «game_map_versions» ya existe`. La BD local `glory_backend_wandorius` tenía objetos de GAME-01 creados fuera de sqlx (prototipado/agente paralelo) sin fila en `_sqlx_migrations` (historial llegaba solo a `20260801130000`). El detector de `glory-rs/scripts/dev.mjs` solo reconocía `VersionMissing|VersionMismatch|previously applied but has been modified`, así que salía con `No se pudieron aplicar las migraciones locales.` en vez de auto-recuperarse.
- **Arreglo raíz:** se extendió el detector para que el drift de `already exists` / `ya existe` (SQLSTATE 42P07, objetos presentes fuera del historial de sqlx) entre al flujo de reset del schema `public` de desarrollo y reaplicación, igual que las otras clases de incompatibilidad. Una tabla creada fuera de sqlx + sin registro es el mismo drift que el historial faltante; el reset del dev-DB es la cura diseñada por el propio launcher.
- **Verificación real:** `npm run dev` → `Migraciones incompatibles o drift en glory_backend_wandorius; reseteando schema public de desarrollo.` → reset → reaplicación completa de la cascada (incluye 140000–170000 del juego) → `Iniciando backend (cargo run --bin glory-backend) y frontend (vite)` → Vite en `http://localhost:5174/`. El proxy dev devuelve `ECONNREFUSED` solo mientras el backend compila (normal).
- **Archivos:** `glory-rs/scripts/dev.mjs` (submódulo `glory-rs`, commit `f3ab77f`).
- **Gotchas:**
  - El fix vive en el submódulo `glory-rs` (repo `github.com/1ndoryu/glory-rs-framework.git`). El puntero del submódulo NO se actualizó en el repo padre porque `main` del submódulo tiene un commit ajeno sin pushear (`e6ec191 fix: harden cargo tmp cleanup`); el push de `main` del submódulo queda diferido para coordinar con el otro agente.
  - No se tocó ningún archivo del otro agente (GAME-01 / 297A-48 / 297A-50) ni el `roadmap.md` (tiene ediciones concurrentes).
  - El perfil de PowerShell de la terminal imprime un warning de `SUPERMEMORY_API_KEY` al abrir shells; es ruido ajeno, no bloquea.
- **Sentinel:** no aplica (archivo JS del framework, fuera de los analyzers del repo).
- **GLORY:** el fix ya vive en el dev launcher agnóstico (`glory-rs/scripts/dev.mjs`), que pertenece al framework.
