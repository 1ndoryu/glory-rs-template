## 038A-1 — Fix `npm run dev`: kill de árbol de procesos en Windows + limpieza de huérfanos

- **Qué:** `npm run dev` fallaba siempre ("Acceso denegado (os error 5)") y la poda de targets no liberaba espacio (20.3 GB > límite 15 GB) por procesos huérfanos de una instancia dev previa: `cargo` (PID 18624) y `glory-backend.exe` (PID 16120) seguían vivos; `child.kill()` de Node en Windows solo mata al hijo directo y deja huérfanos los nietos (cargo → glory-backend). El huérfano de cargo hacía que `clean-cargo-target.ps1` detectara "build activo" y saltara TODAS las fases de limpieza. Se corrigió `glory-rs/scripts/dev.mjs` con 3 cambios:
  - `killProcessTree(pid)`: usa `taskkill /PID <pid> /T /F` para matar el árbol completo en Windows.
  - `cleanup()`: al cerrar dev, mata árboles (antes `child.kill()`).
  - `killStaleProjectProcesses(cargoTargetDir, binName)`: al arrancar, mata binarios huérfanos de instancias previas SOLO si no hay un marcador vivo `.glory-cargo-active-*.json` (protege instancias legítimas).
- **Archivos:** `glory-rs/scripts/dev.mjs` (80 inserciones, 1 borrado). Submódulo commit `15c5ad6` pusheado a `glory-rs-framework` main; puntero del submódulo staged en la raíz.
- **Verificación real:** se mataron los huérfanos, la poda bajó `C:\tmp` de 20256 MB → 13458 MB (bajo el límite 15360 MB), y `npm run dev` volvió a arrancar: pre-cleanup "13473.62 MB / 15360 MB", vite en 5174, backend compilado, puerto 3000 LISTENING, `/api/health` 200. `node --check` PASS sobre dev.mjs.
- **Gotchas:**
  - `child.kill()` en Windows NO mata nietos; hay que usar `taskkill /T /F`.
  - Un proceso cargo huérfano SIN marcador de actividad bloquea la poda completa (test de seguridad de `clean-cargo-target.ps1`). Por eso el kill de huérfanos se hace ANTES del pre-cleanup.
  - El marcador `.glory-cargo-active-*.json` con PID vivo es la señal de "instancia legítima": si existe, no se matan procesos (evita romper un dev activo de otro agente).
- **Sentinel:** no aplica regla nueva (lógica de proceso de framework, no código de proyecto).
- **GLORY:** el fix vive en `glory-rs/scripts/dev.mjs` = framework Glory (agnóstico, beneficia a todos los proyectos del template).
