# Tareas completadas — 2026-08-03

## 028A-13 — Backend de gobernanza del workspace (control/validar/activar)

- **Qué:** se implementó la gobernanza real de releases para evitar que una release incompleta quede vigente sin que el admin lo note (caso Papelera desaparecida por v4). Migración `20260803000000_028a13_release_activation` añade `is_active BOOLEAN NOT NULL DEFAULT false` a `workspace_releases` + índice único parcial `idx_workspace_releases_active WHERE is_active` (solo una activa). Endpoints nuevos:
  - `GET /api/admin/workspace/control` → estado actual (activa, nodos, fecha, autor, última, total).
  - `POST /api/admin/workspace/releases/{version}/validate` → dry-run de validación estructural + refs rotos sin escribir.
  - `POST /api/admin/workspace/releases/{version}/activate?force=true` → activación explícita (guard: rechaza refs rotos con 422 salvo `force`).
  - `list_releases` pasa a DTO ligero (versión, fecha, autor, `nodeCount`, summary, `diffFrom`, `isActive`) sin árbol completo.
- **Archivos:** `migrations/20260803000000_028a13_release_activation.up.sql` / `.down.sql`, `src/handlers/mod.rs`, `src/handlers/workspace_handler.rs`, `src/models/workspace/mod.rs`, `src/models/workspace/release_validation.rs`, `src/repositories/workspace_repo.rs`, `src/services/workspace_svc.rs`, `frontend/src/api/generated/**` (regenerado con Orval v8.6.2: `getWorkspaceControl`, `validateRelease`, `activateRelease` + schemas).
- **Verificación real:** gate `npm run task:check -- 028A-13` **PASS**; en vivo con sesión admin + CSRF: `validate v3` → 200 `valid:true`, `activate v3` → 200, `control` → `activeVersion:3, activeNodeCount:14, latestVersion:4, totalReleases:4`; `GET /api/workspace/release` sirve v3 con 14 nodos incl. `trash` (Papelera restaurada).
- **Gotchas:**
  - **Bug camelCase:** los DTOs nuevos salieron con `rename_all` por defecto (snake_case) mientras `BrokenResourceRef` ya era camelCase → contrato inconsistente. Corregido con `#[serde(rename_all = "camelCase")]` en `ReleaseListItem`, `ReleaseControlResponse`, `ReleaseValidationResponse` y `ReleaseTreeIssue`; verificado en vivo.
  - **Incidente "todas las releases inactivas":** al empezar la sesión ninguna release estaba activa (mutación externa, probablemente otro agente Codex ejecutando una versión intermedia del backend contra la misma BD dev). El código propio no producía esos POSTs (transcripción reconstruida + logs del backend sin POSTs). Se resolvió activando v3 vía API; esto **motivó** el trabajo del panel (028A-14): la clase de incidente debe ser prevenible desde la UI.
- **Sentinel:** no aplica regla nueva.
- **GLORY:** la gobernanza de releases es específica de wandori.us; el patrón `is_active` + índice parcial podría extraerse al framework si otro sitio lo necesita.

## 028A-14 — Panel "Escritorio" en la app Admin

- **Qué:** nueva pestaña **"escritorio"** (primera del Admin) con panel de gobernanza del workspace:
  - **Estado actual:** tarjetas con versión activa, nodos, fecha de publicación, última publicada y total; **aviso** cuando la activa no es la última publicada (el caso Papelera).
  - **Historial:** lista de releases con badge activa/inactiva, nº nodos y fecha; botones **validar** (dry-run → detalle con issues/brokenRefs) y **activar** (confirmación + guard de validez en el propio flujo).
  - **Acción de franja:** "+ publicar release" → `publishWorkspace()` (publica estado actual del workspace con overlay y limpia el overlay).
- **Archivos:** `frontend/src/pages/admin-workspace.ts` (nuevo), `frontend/src/pages/admin.ts` (tab + case + dispose), `frontend/src/services/workspace.service.ts` (`getControl`, `validateVersion`, `activateVersion`, interfaces `ReleaseControl`/`ReleaseValidation`, `ReleaseListItem` ampliado), `frontend/src/styles/pages.css` (estilos del panel).
- **Verificación real:** gate `npm run task:check -- 028A-14` **PASS** (30 archivos, full). Navegador desktop (localhost:5174): tab "escritorio" visible, **detectó el estado sin release activa** (mutación externa había publicado v5 de 3 nodos y dejado v1..v5 inactivas), validó v3 (dry-run "estructura validada... lista para activar"), la activó desde la UI (confirmación → toast → re-render con v3 "activa" y el aviso "la version activa (v3) no es la ultima publicada (v5)"), y `GET /api/workspace/release` volvió a servir v3 con 14 nodos incl. `trash`.
- **Gotchas:**
  - `safeRun` espera una **Promise** (no una función); `showToast(msg, duration)` recibe **duración numérica** como 2º arg (no tipo); `tryCatch` devuelve `{ok:false,error:string}` (no objeto `.message`). Se usó `tryCatch` + `showToast` manual para control fino del mensaje.
  - El patrón del panel sigue `admin-projects.ts`: WeakMaps de cleanups/generaciones + guard de generación tras cada await.
  - El DTO del wire es **camelCase** (backend con `rename_all`), el servicio lo mapea a snake_case interno (convención del archivo).
- **Sentinel:** no aplica regla nueva.
- **GLORY:** no aplica (UI específica de wandori.us).
