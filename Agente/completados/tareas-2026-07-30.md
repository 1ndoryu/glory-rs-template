## 297A-11 — Workspace público y overlay invitado (parcial)

### Auditoría arquitectónica profunda

- Auditoría de arquitectura y escalabilidad del frontend (~15,000 líneas).
- 3 violaciones de tamaño identificadas (command-registration 725, workspace-store 430, desktop-shell 419).
- 5 problemas de escalabilidad (circular deps, store sin event typing, CSS sin layers, sin lazy loading, CommandRegistry sin namespaces).
- 1 falla arquitectónica crítica: Finder era un preview hardcodeado, no un file browser.
- Gap de modelo de datos: `WorkspaceNodeType` faltaba `'resource'` (manual §6.2 define 4 tipos, implementación solo 3).
- `ResourceTypeRegistry` existía pero ningún componente lo usaba.
- Pipeline roto: backend→workspace→Finder no existía.

- `WorkspaceNodeType` incluye `'resource'` + `WorkspaceResourceKind` + `resourceKind` field. (`types.ts`)
- `RenderContext.params` para parámetros de instancia. (`lifecycle.ts`)
- `WindowEntry.params/_paramKey` + `openWindow()` con params y titleOverride. (`window-manager.ts`)
- `openAppWindow(appId, params?)` con dedup non-singleton via `_paramKey`. (`route-app-adapter.ts`)
- Finder reescrito completo: lee `workspaceStore`, breadcrumb, drag/drop, context menu, `ResourceTypeRegistry`. (`finder-preview.ts`)
- Finder `singleton: false`. (`app-registration.ts`)
- Carpetas abren con `folderId`, recursos resueltos via `resolveResourceType`. (`desktop-shell.ts`, `workspace-icon-grid.ts`)
- Gallery cambiado de `type: 'app'` a `type: 'folder'` en default-release.ts.
- Título dinámico de ventana Finder por nombre de carpeta.
- Validación de nombres duplicados en `createFolder()`.
